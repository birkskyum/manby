import { Card, CardGrid } from '@astrojs/starlight/components';

manby takes tippecanoe's options, so a tippecanoe command works as it is:

```sh
manby -zg --drop-densest-as-needed -o places.pmtiles places.geojson
```

<CardGrid>
	<Card title="tippecanoe's tiles" icon="approve-check">
		manby makes the tiles tippecanoe makes, for every option it supports. All 188 of tippecanoe's
		expected test outputs match, from GeoJSON and from Geobuf.
	</Card>
	<Card title="Every core, all the time" icon="rocket">
		The features stay in memory, sorted once. The tile pyramid is made on every core at once, big
		tiles are split across threads, and oversized tiles are retried on data already in memory.
	</Card>
	<Card title="Less memory" icon="laptop">
		On every benchmark manby's peak memory is below tippecanoe's, on macOS and on Linux, and less
		than half of it for the points on a Mac.
	</Card>
	<Card title="Larger than memory" icon="document">
		With `--memory-budget`, 40 million points (5.6 GB) take 79 seconds in 1.1 GB on a Mac, where tippecanoe
		takes 652 seconds and 10 GB.
	</Card>
	<Card title="tile-join too" icon="puzzle">
		`manby join` merges, joins, filters and converts tilesets like tile-join, with the same tiles, two
		to thirty-five times faster.
	</Card>
	<Card title="PMTiles directly" icon="star">
		PMTiles archives are written directly, without the SQLite database tippecanoe goes through.
		MBTiles and directories of tiles work too.
	</Card>
</CardGrid>
